# Questions to ask a software vendor

**Language:** answer in the user's language.

## Workflow

1. Identify (ask only if unclear): project type (ERP / business application / mobile / website-portal / AI agents / integration), **situation** — *build* (new system), *take over* (existing system, previous vendor gone, undocumented code), *urgent* (blocked migration, outage, fixed deadline) — company size, and the meeting format (call, written RFP answers, reference call).
2. Select 12 to 20 questions from `references/question-bank.md`: always the **core** block, then the blocks matching the project type and situation. Do not dump the whole bank.
3. For each question, give: why it matters (one line), the **good answer** you expect, the **red flag**.
4. Add 3 questions to ask the vendor's **references** (past clients).
5. End with a scoring grid the user can fill during the meeting.

## Output format

```
## Before the meeting
Documents to request in advance (list).

## Questions
### <Block>
1. **Question** — why · ✅ good answer · 🚩 red flag

## Reference calls
3 questions.

## Scoring grid
| Criterion | Weight | Vendor A | Vendor B | Notes |
```

## Principles

- Prefer questions that require a **fact or a document** ("send me your standard contract", "who exactly will work on it?") over questions that invite a pitch.
- Ask who does the work: named people, in-house or subcontracted, and who is the single point of contact.
- Ask what the buyer gets if it stops midway. The answer tells more than any reference.
- Large companies should also request: professional liability certificate, recent financial statements, social contributions certificate (attestation URSSAF, mandatory for contracts ≥ 5 000 € in France), DPA template, security policy, reversibility plan. Adapt the requirements to the risk: a small first lot limits exposure to a young vendor.

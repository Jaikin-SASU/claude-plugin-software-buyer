# Question bank

Format: **Question** — ✅ good answer · 🚩 red flag

## Core (always)
1. **Who exactly will work on the project, and are they employees or subcontractors?** — ✅ named people, roles, declared subcontractors · 🚩 "a team will be assigned", anonymous offshore subcontracting.
2. **In whose name are the code repository, hosting, domain and store accounts — from day one?** — ✅ the client's, with delegated access · 🚩 "we host everything, we'll transfer at the end".
3. **Is your price a fixed price with a cap, or an estimate?** — ✅ fixed price per lot, nothing invoiced above without a signed amendment · 🚩 "estimated days", "adjusted to actual time".
4. **What do I own and what do I pay if I stop after the first phase?** — ✅ what is paid is yours, bounded exit · 🚩 remaining months due, code not transferred until the end.
5. **How does acceptance work?** — ✅ test period, written acceptance report per lot, fix delays · 🚩 "you validate by using it".
6. **What happens after go-live: warranty, maintenance, is maintenance mandatory?** — ✅ warranty ≥ 3 months, optional maintenance priced separately · 🚩 multi-year maintenance required to keep using the software.
7. **Can another team take over without you? Show me a documentation example.** — ✅ documentation standard, redeployable by an outside developer · 🚩 "our framework is proprietary".
8. **What do you need from us, and when?** — ✅ a decision-maker available, data accessible in week 1, scope frozen at end of framing · 🚩 no requirements on the client side (the delays will be yours).
9. **Can you send your standard contract before we go further?** — ✅ yes, today · 🚩 "we'll see after the quote".

## Build (new system)
10. **How do you map processes and data before quoting?** — ✅ paid framing or discovery phase with a written deliverable · 🚩 firm quote after one call on a complex scope.
11. **Standard software or custom — did you price both?** — ✅ both options priced, criteria to choose · 🚩 only the solution they resell.
12. **How are shared data mastered (customers, products, stock)?** — ✅ one master per data, stated · 🚩 "we sync everything both ways".
13. **How is the go-live done, and can you roll back?** — ✅ rehearsed migration, rollback tested before cut-over · 🚩 "big bang on Monday".

## Take over (existing system)
14. **How do you audit a system you did not build?** — ✅ audit deliverable: inventory, accesses, risks, documentation · 🚩 "we'll rewrite it, it's faster".
15. **First step on day one?** — ✅ secure the accesses and put them in the client's name, backups verified · 🚩 starts coding features.
16. **When do you recommend rewriting instead of maintaining?** — ✅ cost comparison over several years, rewriting is not a reflex · 🚩 rewriting proposed before reading the code.

## Urgent
17. **Can you fix scope and price before starting?** — ✅ sprint with scope and price set in writing · 🚩 open-ended time and materials "until it works".
18. **What is your rollback if the fix fails?** — ✅ named rollback plan · 🚩 none.

## ERP / Odoo
19. **Which requirements are covered by standard modules, which need development?** — ✅ written matrix per requirement · 🚩 "everything is standard" on a specific business.
20. **Editor licences: which plan, how many users, at which list price and date?** — ✅ list prices dated, confirmed at subscription, no multi-year projection · 🚩 licences omitted or "0 €".
21. **Are you allowed to modify the source (hosting plan constraints)?** — ✅ explains what the chosen hosting plan allows · 🚩 custom modules on a plan that does not accept them.

## Mobile
22. **Native, cross-platform or web app — why?** — ✅ justified by offline, device features, budget · 🚩 one answer for every project.
23. **Offline mode and sync conflicts?** — ✅ explains the conflict rule · 🚩 "the network is always available".
24. **Store publication in whose account, and who handles store reviews?** — ✅ client's developer accounts · 🚩 vendor's account.

## AI agents / automation
25. **Where does inference run, and what data leaves our systems?** — ✅ named provider and region, pseudonymisation · 🚩 "we use ChatGPT" with no data policy.
26. **How do we measure that the AI works?** — ✅ baseline metrics, pilot, then scale · 🚩 no metric, only demos.
27. **Who validates the AI's output before it acts?** — ✅ human oversight where decisions matter; decision-support tool · 🚩 fully autonomous on sensitive actions.
28. **Your role and ours under the EU AI Act?** — ✅ client = deployer, documentation provided · 🚩 unaware.

## Security and compliance
29. **How do you handle personal data (GDPR)?** — ✅ DPA before access to real data, sub-processors listed · 🚩 "we're GDPR compliant" with no DPA.
30. **Security tests and patching?** — ✅ internal review + external test for exposed apps, critical patches within a stated delay · 🚩 none.
31. **Backups: when was the last restore test?** — ✅ a date · 🚩 "backups are automatic".

## Reference calls
- Did the project end at the quoted price? If not, why?
- Did you get the code, accesses and documentation without asking twice?
- Would you give them your next project, and what would you change in the contract?
